# Issue #206: Testcontainers Reaper on CI

`Expected Reaper to map exposed port 8080` in Testcontainers Node v10.28.0 is thrown only when it discovers and reuses an already-running Ryuk/Reaper container and Docker metadata has no published (`PublicPort`) mapping for container port 8080. The new-Reaper path explicitly exposes 8080. The error therefore points to an unexpected existing Reaper record, not by itself to a PostgreSQL test failure or a general inability to reach Docker. [v10.28.0 Reaper source](https://github.com/testcontainers/testcontainers-node/blob/v10.28.0/packages/testcontainers/src/reaper/reaper.ts#L48-L85)

A failure on local Windows Docker Desktop alone does **not** imply the Ubuntu GitHub runner will fail. Testcontainers documents Docker as supported, and GitHub-hosted runners provision a fresh VM for each job and decommission it afterward; GitHub specifies Ubuntu for container/service-container jobs. A stale Reaper from another CI job should not persist on a hosted runner. If CI reproduces this, inspect for a running Ryuk already present within that job/daemon before changing runner configuration. [Testcontainers supported runtimes](https://node.testcontainers.org/supported-container-runtimes/), [GitHub-hosted runner lifecycle](https://docs.github.com/en/actions/how-tos/manage-runners/github-hosted-runners/use-github-hosted-runners), [GitHub container runner requirements](https://docs.github.com/en/actions/tutorials/use-containerized-services/create-postgresql-service-containers)

## CI diagnostics

- For a diagnostic rerun, set `DEBUG: testcontainers` on the e2e step and capture `docker info` plus `docker ps -a --filter label=org.testcontainers.ryuk=true --format 'table {{.ID}}\t{{.Image}}\t{{.Status}}\t{{.Ports}}\t{{.Names}}'`. The logs reveal whether Testcontainers reused a Reaper; the container listing shows whether port 8080 has a host mapping. [Testcontainers logging config](https://node.testcontainers.org/configuration/), [v10.28.0 Reaper label/source](https://github.com/testcontainers/testcontainers-node/blob/v10.28.0/packages/testcontainers/src/utils/labels.ts), [Docker container listing filters](https://docs.docker.com/reference/cli/docker/container/ls/)
- No CI override is justified preemptively: `TESTCONTAINERS_HOST_OVERRIDE` changes the host used for exposed ports, `TESTCONTAINERS_DOCKER_SOCKET_OVERRIDE` changes Ryuk's Docker socket path, and `TESTCONTAINERS_RYUK_PORT` selects a host port when creating a new Reaper. None repairs a reused container missing its published port. `TESTCONTAINERS_RYUK_DISABLED=true` bypasses the Reaper and changes automatic cleanup, so it is not an equivalent fix. [Testcontainers configuration](https://node.testcontainers.org/configuration/), [v10.28.0 Reaper source](https://github.com/testcontainers/testcontainers-node/blob/v10.28.0/packages/testcontainers/src/reaper/reaper.ts#L48-L85)
