# AR Ledger Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add an append-only `ledger_events` stream that records every AR money movement (`Receivable` balance changes and `Payment` credit-balance changes) as a dual-write alongside the existing persisted rollups, giving the product a single query surface for "how did this organization's AR money move" without joining `Receivable`/`Payment`/`PaymentAllocation`.

**Architecture:** New `ledger` module (`apps/backend/src/modules/ledger/`) following this repo's 4-layer Clean Architecture, built as a near-exact structural mirror of `apps/backend/src/modules/receivable-balance-history/` (the closest existing analog: an append-only, insert-only, tenant-scoped history table with a recorder service). A `LedgerEventRecorderService` is injected into the five existing use cases that change AR money state; each call site appends one or two `LedgerEvent` rows (receivable-side and/or payment-side) inside its *existing* transaction. No existing rollup, table, or read path changes.

**Tech Stack:** NestJS 11, TypeORM 1.1 migrations (raw SQL, matching this repo's migration style), Jest for unit tests.

**Spec:** `CONTEXT.md` ("AR Ledger" section) and `docs/adr/0020-ar-ledger-event-sourced-not-double-entry.md` in this worktree — read both before starting; this plan implements the model they define.

## Global Constraints

- Money fields are `bigint` columns, integer VND units — never float/decimal.
- Every ledger append happens inside the same DB transaction as the triggering write (no separate transaction, no post-commit ledger write for the receivable/payment-side events — only domain event emission, e.g. `eventPublisher.emit`, happens after commit, unchanged from today).
- `domain/` files (`apps/backend/src/modules/ledger/domain/*`) must not import NestJS or TypeORM.
- `application/` files must not import TypeORM concrete classes except `EntityManager`/`DataSource` per AGENTS.md's allowed exception; never throw `HttpException` — throw `AppError`.
- `infrastructure/` repository must scope every read by `organizationId` from `TenantContextService` and use an explicit `toOrm()` mapper — never `as`/`as unknown as`.
- Ledger rows are inserted with `.insert()`, never `.save()`/`.update()` — enforces append-only, matching `typeorm-receivable-balance-history.repository.ts`.
- `RED → GREEN → REFACTOR`: every task with production logic starts with a failing test.
- Do not touch `Receivable.paidAmount`, `Payment.allocatedAmount`, `ReceivableBalanceHistory`, or any existing read path (aging dashboard, reporting, receivable/payment list) — this is additive only.

## Domain Model Reference

`LedgerEvent` fields (see `CONTEXT.md`):

| Field | Type | Notes |
|---|---|---|
| `id` | `string` (uuid) | |
| `organizationId` | `string` | |
| `subjectType` | `LedgerEventSubjectType` | `RECEIVABLE` \| `PAYMENT` |
| `subjectId` | `string` (uuid) | `receivableId` or `paymentId` |
| `kind` | `LedgerEventKind` | see table below |
| `amount` | `number` | signed integer VND; positive = subject's balance increased, negative = decreased. Never `0`. |
| `effectiveAt` | `Date` | |
| `transitionReferenceId` | `string \| null` | allocation id, when applicable |
| `createdAt` | `Date` | |

`LedgerEventKind` → subject → sign, one row per existing `changeSource`/action:

| Kind | Subject | Sign | Fired from |
|---|---|---|---|
| `RECEIVABLE_CREATED` | RECEIVABLE | `+originalAmount` | `CreateReceivableUseCase` |
| `RECEIVABLE_ALLOCATED` | RECEIVABLE | `-amount` | `AllocatePaymentUseCase.allocateWithinTransaction` |
| `RECEIVABLE_ALLOCATION_UNDONE` | RECEIVABLE | `+amount` | `UndoPaymentAllocationUseCase` |
| `RECEIVABLE_CANCELLED` | RECEIVABLE | `-remainingAmount` (pre-transition) | `ReceivableTransitionRunnerService` (via `CancelReceivableUseCase`) |
| `RECEIVABLE_WRITTEN_OFF` | RECEIVABLE | `-remainingAmount` (pre-transition) | `ReceivableTransitionRunnerService` (via `WriteOffReceivableUseCase`) |
| `RECEIVABLE_ROLLOUT_BASELINE` | RECEIVABLE | `+remainingAmount` (current) | rollout-baseline migration |
| `PAYMENT_RECEIVED` | PAYMENT | `+totalAmount` | wherever `new Payment(...)` is saved: `process-webhook.usecase.ts`, `match-bank-transaction.usecase.ts`, `mark-prepaid-bank-transaction.usecase.ts` |
| `PAYMENT_ALLOCATED` | PAYMENT | `-amount` | `AllocatePaymentUseCase.allocateWithinTransaction` |
| `PAYMENT_ALLOCATION_UNDONE` | PAYMENT | `+amount` | `UndoPaymentAllocationUseCase` |
| `PAYMENT_ROLLOUT_BASELINE` | PAYMENT | `+unallocatedAmount` (current) | rollout-baseline migration |

```typescript
// apps/backend/src/modules/ledger/infrastructure/typeorm-ledger-event.repository.ts
import { Injectable } from '@nestjs/common';
import { InjectRepository } from '@nestjs/typeorm';
import type { EntityManager, Repository } from 'typeorm';
import { AppError } from '../../../common/errors/app-error';
import { ErrorCode } from '../../../common/errors/error-code';
import { TenantContextService } from '../../../common/tenancy/tenant-context';
import type { ILedgerEventRepository } from '../application/ledger-event-repository.port';
import type { LedgerEvent } from '../domain/ledger-event';
import { LedgerEventOrmEntity } from './ledger-event.orm-entity';

// Explicit entry → ORM translation: the compiler checks every field, so a
// drift between the two shapes fails here instead of being cast away.
// `sequence` is a DB-generated bigserial and is omitted from inserts.
function toOrm(entry: LedgerEvent): Omit<LedgerEventOrmEntity, 'sequence'> {
  return {
    id: entry.id,
    organizationId: entry.organizationId,
    subjectType: entry.subjectType,
    subjectId: entry.subjectId,
    kind: entry.kind,
    amount: entry.amount,
    effectiveAt: entry.effectiveAt,
    transitionReferenceId: entry.transitionReferenceId,
    createdAt: entry.createdAt,
  };
}

@Injectable()
export class TypeOrmLedgerEventRepository implements ILedgerEventRepository {
  constructor(
    @InjectRepository(LedgerEventOrmEntity)
    private readonly ormRepo: Repository<LedgerEventOrmEntity>,
    private readonly tenantContext: TenantContextService,
  ) {}

  async append(entry: LedgerEvent, manager?: EntityManager): Promise<void> {
    if (entry.organizationId !== this.tenantContext.getOrganizationId()) {
      throw new AppError(
        ErrorCode.TENANT_MISMATCH,
        'Không thể ghi dữ liệu cho tổ chức khác',
      );
    }

    // insert() (not save()) keeps the ledger append-only.
    const row = toOrm(entry);
    if (manager) {
      await manager.getRepository(LedgerEventOrmEntity).insert(row);
      return;
    }
    await this.ormRepo.insert(row);
  }
}
```

```typescript
  organizationId: string;
  subjectType: LedgerEventSubjectType;
  subjectId: string;
  kind: LedgerEventKind;
  amount: number;
  effectiveAt?: Date;
  transitionReferenceId?: string;
  manager?: EntityManager;
}

@Injectable()
export class LedgerEventRecorderService {
  constructor(
    @Inject(LEDGER_EVENT_REPOSITORY)
    private readonly repo: ILedgerEventRepository,
  ) {}

  async record(input: RecordLedgerEventInput): Promise<void> {
    assertValidLedgerEventAmount(input.amount);
    const now = new Date();
    await this.repo.append(
      {
        id: randomUUID(),
        organizationId: input.organizationId,
        subjectType: input.subjectType,
        subjectId: input.subjectId,
        kind: input.kind,
        amount: input.amount,
        effectiveAt: input.effectiveAt ?? now,
        transitionReferenceId: input.transitionReferenceId ?? null,
        createdAt: now,
      },
      input.manager,
    );
  }
}
```

```typescript
// apps/backend/src/modules/ledger/infrastructure/typeorm-ledger-event-query.ts
import { Injectable } from '@nestjs/common';
import { InjectRepository } from '@nestjs/typeorm';
import type { Repository } from 'typeorm';
import type {
  ILedgerEventQuery,
  LedgerEventListFilters,
  LedgerEventListPage,
} from '../application/ledger-event-query.port';
import { LedgerEventOrmEntity } from './ledger-event.orm-entity';

function toDomain(row: LedgerEventOrmEntity) {
  return {
    id: row.id,
    organizationId: row.organizationId,
    subjectType: row.subjectType,
    subjectId: row.subjectId,
    kind: row.kind,
    amount: Number(row.amount),
    effectiveAt: row.effectiveAt,
    transitionReferenceId: row.transitionReferenceId,
    createdAt: row.createdAt,
  };
}

@Injectable()
export class TypeOrmLedgerEventQuery implements ILedgerEventQuery {
  constructor(
    @InjectRepository(LedgerEventOrmEntity)
    private readonly ormRepo: Repository<LedgerEventOrmEntity>,
  ) {}

  async list(
    organizationId: string,
    filters: LedgerEventListFilters,
    page: number,
    limit: number,
  ): Promise<LedgerEventListPage> {
    const qb = this.ormRepo
      .createQueryBuilder('event')
      .andWhere('event.organizationId = :organizationId', { organizationId })
      .andWhere('event.subjectType = :subjectType', {
        subjectType: filters.subjectType,
      })
      .andWhere('event.subjectId = :subjectId', {
        subjectId: filters.subjectId,
      })
      .orderBy('event.effectiveAt', 'DESC')
      .addOrderBy('event.sequence', 'DESC')
      .skip((page - 1) * limit)
      .take(limit);

    const [rows, total] = await qb.getManyAndCount();
    return { items: rows.map(toDomain), total, page, limit };
  }
}
```
